이 문서는 확인된 세 가지 변경을 중심으로 **문제 → 구현 선택 → 검증 근거**를 설명합니다. 코드는 원본 소스를 옮긴 것이 아니라 동작을 설명하기 위한 의사코드입니다.

## 1. 결과를 다시 판단할 수 있는 공유 화면

### 문제를 좁힌 방법

이슈 댓글에 결과 링크가 있어도, 링크 안에서 테스트 절차와 이미지를 따로 찾아야 하면 다른 담당자가 판단 근거를 확인하기 어렵습니다. 댓글 형식은 유지하고 링크의 목적지 화면을 개선하는 범위로 정했습니다.

### 구현 선택

| 선택 | 이유 | 고려한 비용 |
|---|---|---|
| TC별 카드와 두 열 구성 | 증적과 기대결과를 같은 위치에서 비교 | 화면 폭에 따른 공간 배분 필요 |
| 썸네일·이전/다음·확대 | 여러 촬영을 맥락 안에서 확인 | 선택 상태와 키보드 포커스 관리 필요 |
| 실행 당시 문서 표시 | 현재 문서 변경과 과거 결과의 근거를 구분 | 당시 문서가 없을 때 별도 안내 필요 |
| 게시 범위의 증적만 노출 | 공유 링크가 의도한 결과만 제공 | 내부 화면과 별도 표시 경로 유지 |

외부 독자가 문구·이미지를 보기만 하는 화면도 입력 문자열을 안전하게 출력해야 합니다. HTML 이스케이프와 허용 스크립트의 정확한 해시를 검사하고, 확대 창을 닫으면 이전 요소로 포커스가 돌아오는지 확인했습니다.

## 2. 본문이 없다는 것과 가져오지 못한 것을 구분

### 오류가 생기는 지점

목록 조회와 본문 조회는 별개입니다. 목록에서 받은 제목이 화면에 있더라도 본문 요청은 실패할 수 있습니다. 제목이 있다는 이유만으로 본문까지 확보된 것으로 취급하면 AI 분석의 입력 근거가 부족해집니다.

```text
본문 조회 중
  ├─ 성공 → 본문 표시 → 분석 가능 여부 판단
  └─ 실패 → 조회 실패 안내 + 다시 불러오기 → 분석 제한
                 └─ 재시도 성공 → 오류 해제 + 본문 표시
```

```python
# 동작 설명용 의사코드
if detail_request.failed:
    show_source_error(detail_request.reason)
    disable_analysis()
elif detail_request.succeeded:
    show_description(detail_request.description)
    clear_source_error()
```

버튼을 추가하는 것으로 끝내지 않고, 실패 응답과 정상 응답을 순서대로 반환하는 테스트로 오류 표시·재시도·본문 복구를 확인했습니다. 인증·권한·네트워크 오류를 무조건 다른 조회 방식으로 우회하지 않도록 서버의 호환 처리 범위도 제한했습니다.

## 3. 테스트 코드 자체의 잘못된 요청 가로채기 수정

### 관찰

가상 API를 붙인 회귀 검사에서 화면이 비어 보였습니다. 기다리는 시간을 늘리기 전에 요청 경로를 확인했고, API 응답을 대신하는 규칙이 프런트엔드 JavaScript 모듈까지 가로채고 있음을 찾았습니다.

### 원인과 수정

```text
넓은 규칙: **/api/**
  → /src/shared/api/... 같은 화면 코드 경로까지 일치할 수 있음

제한한 규칙: <검사 대상 origin>/api/**
  → 해당 서버의 실제 API 경로만 가로챔
```

제품의 실패, 자동화 코드의 실패, 검사 환경의 실패를 구분해야 결과를 믿을 수 있습니다. 수정 이후 화면 전환·재시도와 함께 페이지 오류 및 변경 요청이 없는지 검사했습니다.

## 이 기록이 보여 주는 작업 범위

| 영역 | 구체적인 작업 |
|---|---|
| QA 설계 | 통과 조건을 행 개수·내용·복구 상태처럼 비교 가능한 조건으로 정의 |
| 플랫폼 구현 | 실행 근거와 검수 상태를 표현하는 결과 UI, 오류 상태와 재시도 흐름 개선 |
| AI 지원 개발 | 요구사항·제약을 정하고 코드 작성과 실패 분석을 지원받은 뒤 코드 검사로 확인 |
| 결과 설명 | 가상 UI 검증과 실제 제품 검증을 구분하고 공개 가능한 자료로 재구성 |

플랫폼 전체의 단독 개발이나 개인별 기여율을 의미하지 않습니다. 이 저장소는 확인된 변경과 그 판단 근거를 중심으로 작성했습니다.
